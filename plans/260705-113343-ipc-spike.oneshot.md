# One-Shot: IPC Spike
Prove the stdio IPC protocol between a minimal C++ backend and Electron/Vue frontend — full Phase 1 deliverables including JSON commands, UUID correlation, length-prefixed binary framing, progress event streaming, and cross-compilation.

**Target dir:** projects/guava-slicer
**Mode:** greenfield
**Project type:** application

## Stage 0: Context & Use Cases

**Who:** Developer proving IPC architecture before building mesh/slicing features.

**Problem:** Validates C++ backend ↔ Electron/Vue frontend communication over stdio — JSON commands with UUID correlation, binary framing for large payloads, progress streaming for long operations. Every future feature depends on this plumbing.

**Constraints:** C++17/Zig build/-fno-exceptions -fno-rtti, nlohmann/json vendored, Electron + Vue 3, stdio IPC only, cross-compilation (macOS ARM/Intel, Windows x86_64).

**Non-goals:** No real mesh processing, no Three.js viewport, no undo/redo, no persistence.

**Design doc:** `designs/ipc-protocol.md`

### Use Cases

1. **Ping/Echo** — Frontend sends `ping`, backend responds `pong`. Proves JSON round-trip + UUID correlation.
2. **Progress Streaming** — Frontend sends `simulate` with step count, backend streams progress events from worker thread, then terminal response. Proves threading + event streaming.
3. **Binary Frame Transfer** — Frontend sends `get_binary`, backend responds with JSON metadata + binary frame. Proves length-prefixed binary framing.
4. **Cross-Compilation** — `make -s cross` produces binaries for all 3 targets.

## Stage 1: User-Facing Interfaces → Command Console

Single-page Vue app with a command panel: three buttons (Ping, Simulate, Get Binary), a progress bar, and a scrollable log showing raw JSON request/response messages. Directly exposes the IPC protocol for debugging. Minimal UI code — no component library needed.

## Stage 2: Behavior

**Actions:** Send Ping (click → ping/pong round-trip), Run Simulation (click → simulate with progress events from worker thread), Request Binary (click → JSON metadata + binary frame), Spawn Backend (app launch → child_process.spawn), Shutdown Backend (app close → kill child process).

**Inputs:** Button clicks. Step count and byte count use hardcoded defaults.

**Outputs:** Scrollable log with timestamped JSON messages (sent/received). Progress bar during simulate. Backend connected/disconnected status indicator. Backend stderr piped to Electron console.

## Stage 3: Data Model

**Frontend:** IpcMessage (direction, timestamp, raw, parsed), PendingRequest (id, cmd, sentAt, onProgress, onComplete), BackendState (connected, process).

**Backend:** Request (cmd, id, params), Response (id, ok, result/error), ProgressEvent (id, event, data), BinaryFrame (type_byte 0x02 + uint32 LE length + payload).

**Invariants:** One terminal response per request. Progress events reference valid pending IDs. Binary frames follow their describing JSON response. UUID-keyed map prevents duplicates. Mutex-guarded stdout writes prevent interleaving.

## Stage 4: Error Handling → Production-grade

Every failure path produces a meaningful `{ok: false, error: {code, message}}` response. Backend never crashes — all failures (bad JSON, unknown command, thread errors, allocation failures) propagate as error responses to the frontend. Sets the pattern for all future commands.

## Stage 7: Tech Stack → Monorepo with Makefile driver

`backend/` (C++17, Zig build, nlohmann/json vendored) + `frontend/` (Electron + Vue 3, npm). Top-level Makefile wraps both.

### Build & Test Commands
```
build: make -s build   → cd backend && zig build; cd frontend && npm run build
test:  make -s test    → cd backend && zig build test; cd frontend && npm test
cross: make -s cross   → cd backend && zig build cross
run:   make -s run     → build + cd frontend && npm run electron:dev
clean: make -s clean   → cd backend && rm -rf zig-out .zig-cache; cd frontend && rm -rf dist node_modules
```
