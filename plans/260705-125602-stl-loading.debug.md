# Debugging Notes — STL Loading

## Issue 1: Numpad 2/8 orbit direction inverted
**Symptom**: Numpad 8 orbited down, Numpad 2 orbited up (opposite of Blender convention).
**Fix**: Swapped the angle sign for Numpad 2 and 8 in `Viewport.vue` `onKeyDown`.

## Issue 2: Drag-and-drop not loading files
**Symptom**: Drag overlay appeared but dropping an STL file did nothing.
**Cause**: Electron 35 deprecates `File.path` — returns undefined. Need `webUtils.getPathForFile()`.
**Fix**: Exposed `webUtils.getPathForFile` via preload, updated drop handler to use it.

## Issue 3: 10-second delay after parsing 100% on large files
**Symptom**: Progress hit 100%, then UI froze for ~10s before mesh appeared.
**Cause**: ~80MB of binary data serialized through Electron IPC via structured clone (3 calls of 20-40MB each). Additionally, 300 progress events for 3M triangles.
**Fix**: 
- Binary frames written to temp files in main process, paths passed via IPC, renderer reads files directly via `fs.readFileSync` in preload (bypasses structured clone).
- Progress interval increased from 10,000 to 100,000 triangles.
- Required `sandbox: false` in webPreferences for preload to access `fs`.

## Issue 4: No visual feedback during post-parse processing
**Symptom**: After parsing hit 100%, progress bar disappeared but mesh hadn't appeared yet.
**Fix**: Added two-phase progress — "Loading... X%" during parsing, "Processing mesh..." with shimmer animation once the final progress event fires. Covers binary transfer + file I/O + Three.js geometry construction.

## Additional features added during debug
- Numpad 9: snap to back view
- Numpad +/-: zoom in/out
- Drag-and-drop STL files onto viewport
- 3D axis gizmo in bottom-right corner (syncs with camera rotation)
